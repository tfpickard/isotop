# docs

## OVERVIEW
Design rules, roadmap, generated metrics, theory pages, mockups and media. Own file because it holds the precedence
rules for planned work and several files that are generated or are prototypes, not shipped truth.

## WHERE TO LOOK
| Task | File | Symbol / notes |
|---|---|---|
| Rules for every new view | `VIEW_CONVENTIONS.md` | also the CPU/GPU parity tolerance (`CPU/GPU parity`) |
| Pick up a planned item | `ROADMAP.md` | one GitHub issue per item; "How to take an item" |
| Source brief for the eighteen views | `briefs/views-2026-10.md` | wins over a mockup on a mapping |
| Metrics report | `METRICS.md` | generated by `scripts/code_report.py` |
| Theory page for a view | `theory/<view>.md` | pattern in `theory/README.md` |
| Theory diagrams | `theory/figures/make_figures.py` | needs matplotlib and numpy; no gate runs it |
| Visual prototypes | `mockups/*.jpg`, `mockups/code/<view>.py` | numbers and technique, not shipped code |
| README and wiki media | `media/` | webp stills and loops, `renders/`, `figures/*.svg` |
| Plot scripts | `figures/` | has its own `AGENTS.md` |

## CONVENTIONS
- Precedence when sources disagree: the issue, then `VIEW_CONVENTIONS.md`, then the brief. On a mapping the brief beats a mockup.
- Items are named by ID; a name marked "from <ID>" does not exist until that issue merges, so check `main` first.
- One item per PR. The PR body opens with `## Plan`, then `## Decisions`. An open choice is decided brief, mockup,
  prototype, nearest precedent, and recorded under Decisions.
- Theory pages follow the pattern: what you are looking at, history (always), background theory, how isotop implements it,
  faithful/stylized/invented, reading the picture, further reading. Equations are LaTeX in `$...$` or `$$...$$`.
- A theory page quotes constants and function names from `src/`; change them together and run `python3 scripts/code_report.py`.
- Each theory page opens with the view's render from `media/`.
- Media paths are named by the pages and README that link them; `scripts/check_wiki.py` requires every
  raw.githubusercontent `docs/...` link to name a committed file.
- Mockup prototypes write to `$ISOTOP_MOCKUP_OUT`, default `docs/mockups/out`. Shared helpers: `mockkit.py`, `isostyle.py`.
  Three ignore it and need the output path as their first argument: `morph.py` and `murmuration.py` take a directory
  (`main(sys.argv[1])`), and `presets.py` takes the image file it writes.
- Where a prototype is wrong the theory page says so.

## ANTI-PATTERNS
- Do not hand-edit `METRICS.md`; regenerate it.
- Do not run `mockups/code/*.py` as truth or ship them; they are prototypes with their own dependencies (numpy, cv2, PIL).
- Do not copy a mockup's key bindings into a view (hr's `d` is pan-right, so hr uses `m`).
- Do not rely on a "from <ID>" name before that issue is merged.
- Do not start a second item in the same PR.
- Do not change a theory-page constant without the matching `src/` change, or the reverse.

## COMMANDS
- `python3 scripts/code_report.py` regenerates `METRICS.md` and the README block (needs `tokei`).
- `python3 scripts/code_report.py --check` fails when either is stale.
- `python3 -m venv /tmp/figenv && /tmp/figenv/bin/pip install matplotlib numpy && /tmp/figenv/bin/python docs/theory/figures/make_figures.py`
